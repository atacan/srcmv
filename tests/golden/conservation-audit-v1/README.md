# Conservation audit v1 golden vectors

Full serialized `conservation-audit-v1` reports (exactly one UTF-8 JSON value
plus LF per file) generated by the Phase 3 pipeline over the frozen fixture
trees in `tests/fixtures/conservation/`:

```text
read_audit_tree / read_audit_tree_from_manifest   (srcmv-fs, release limits)
  → audit_conservation                            (srcmv-core, stated options/budget)
  → build_audit_report[_with_limits]              (srcmv-protocol, AuditRenderLimits)
  → audit_report_json_line                        (to_json_line: one value + LF)
```

CI compares these files byte-for-byte against real output
(`crates/srcmv-protocol/tests/audit_goldens.rs`). There is no bless escape
hatch: to regenerate, run that test's pipeline steps and commit the diff. The
generator runs in a debug build because one vector relies on the
debug-only `audit_tree_faults` seam (see `inconclusive-skipped-input.json`
below); under `cargo test --release` that single vector is skipped and the
remaining ten are still compared.

Every report validates against
`docs/schema/conservation-audit-v1/report.schema.json`
(`crates/srcmv-protocol/tests/audit_v1.rs`, offline Draft 2020-12 registry)
and satisfies the runtime-only guarantees recomputed from the serialized bytes:
the §9.2 ledger identity, consumed/new-span survivor accounting, digest
spellings, closed vocabularies, and the deterministic §11.1 orderings.
Identical inputs produce byte-identical output across repeated runs, pinned by
a dedicated determinism test.
